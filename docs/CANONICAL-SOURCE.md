# One canonical source checkout

Use the Git checkout of https://github.com/TaylorBeeston/orch3stra for both development and local launch. The owner-selected local convention is `~/dev/ai/video/orch3stra`; another explicit checkout path is supported. Keep it on the reviewed main branch between changes. Do not replace it with an old extracted release or restart a stale working copy.

The r3 dogfood fixes are already included: provider preview waits for bridge initialization (`providers.js`, regression `scripts/check-provider-startup.cjs`); stored thumbnail data URLs decode locally (`storage.js`, regression `scripts/check-storage-decoder.cjs`); timing extension retains explanatory geometry/capacity feedback (`timing-ui.js`). Reconciliation preserves these and the later preferred/exceptional planner policy, exclusive intent-ledger ownership, coordinated bridge shutdown, honest structural preflight and restrictive media serving. The central native engine/media support is shared with the r3 source; this is not a blind overwrite by either tree.

Project data remains at the existing `H3_DATA_DIR`, normally `~/.local/share/h3-director`. That legacy identifier is intentional. Preserve the worker database, upload/output paths, project/media IDs, pairing settings and credentials. Do not move or import data just to rename the source. Portable project backups omit worker-owned rendered videos.

For a local cutover, first coordinate one writer, review the source diff, run fixture/packaging checks and merge the tested change normally. Confirm the worker has no active job and dispatch is paused. Preserve a private rollback source/configuration bundle. Close the old Node bridge, stop the idle worker through its supported shutdown endpoint, then start the canonical checkout with the same existing nonsecret paths, bind address and ports. Do not install dependencies, create generation jobs or change credentials as part of the path switch. Verify the app, existing data and paused queue before archiving former working trees. An older bridge does not have the new shutdown barrier; preserve its state rather than assuming it behaves like the new one.

Use recoverable Trash or an explicitly non-working archive for obsolete copies. Keep a precise path map and rollback instructions outside the public source. Keep source archives separate from active checkouts. Do not delete the retained pre-cutover project-data backup in this consolidation. Archived history, upstream research fixtures and owner-derived examples must not enter the public package.

CPU CI and synthetic browser/recovery tests establish their documented scope only. No new live-model, ASR, GPU, physical-device or hardware-fit validation is implied. A preflight exit 2 means structural checks passed but runtime readiness is still unverified.
